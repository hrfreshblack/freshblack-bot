# Склад (перший модуль ERP) — що це і як розгорнути

## Що вже є

Окремий вебдодаток (`warehouse/`), не Telegram-бот — сторінка в браузері, працює однаково на ноуті й на планшеті. Використовує ту саму Postgres-базу, що й бот (окремі таблиці `products` і `stock_movements`, жодного перетину з таблицями бота).

Що можна робити зараз:
- Додати товар у каталог (код, назва, одиниця, мінімальний запас; або позначити як "тільки під замовлення" — тоді залишок не рахується взагалі).
- Внести рух: приймання виробництва, відвантаження, повернення, списання, коригування плюс/мінус, або "інвентаризація — фактично порахована кількість" (вказуєш скільки порахувала фізично, система сама рахує різницю — так само, як описано в ТЗ, розділ 11).
- Побачити список товарів з поточним залишком, мінімальним запасом і статусом (ОК / Поповнити / Дефіцит), з пошуком.

Чого ще немає (наступні кроки): зелена кава/напівфабрикат (окремі рівні запасів), імпорт SAP, планшетні задачі виробництва, звʼязок із замовленнями напряму.

## Як розгорнути на Railway (одноразово)

1. У тому ж проєкті Railway (`zesty-enthusiasm`, де вже є бот і Postgres) — **+ New → GitHub Repo** → обери той самий репозиторій `freshblack-bot`, але в налаштуваннях нового сервісу постав **Root Directory** = `warehouse`.
2. У Variables нового сервісу додай:
   - `DATABASE_URL` = `${{ Postgres.DATABASE_URL }}` (та сама база, що й у бота)
   - `WAREHOUSE_USER` і `WAREHOUSE_PASSWORD` — придумай логін/пароль для входу (це не обов'язково, але без них сторінка відкрита будь-кому за посиланням)
3. **Settings → Networking → Generate Domain** — отримаєш публічну адресу типу `https://warehouse-production.up.railway.app`.
4. Відкрий цю адресу в браузері — введи логін/пароль (якщо задавала) — готово.
