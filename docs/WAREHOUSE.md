# Склад (перший модуль ERP) — що це і як розгорнути

## Що вже є

Окремий вебдодаток (`warehouse/`), не Telegram-бот — сторінка в браузері, працює однаково на ноуті й на планшеті. Використовує ту саму Postgres-базу, що й бот (окремі таблиці `products` і `stock_movements`, жодного перетину з таблицями бота).

Що можна робити зараз:
- **Товари** — довідник усіх позицій: код, назва, станція, одиниця, чи складський товар, статус (активний / немає в наявності / знято з виробництва). Тут само додається новий товар кнопкою "+ Товар".
- **Склад** — операційний вигляд лише складських товарів: залишок, скільки надійшло і скільки видано, мінімальний запас, стан (ОК / Поповнити / Дефіцит), тут вносяться рухи (приймання виробництва, відвантаження, повернення, списання, коригування, "інвентаризація — фактично порахована кількість" — див. ТЗ розділ 11).
- **Станції** — задачі виробництва по станціях: перемикач "Всі станції" / конкретна станція, діапазон дат (за замовчуванням сьогодні + 6 днів наперед), ручне створення задачі (станція, товар, планова кількість, дата, причина) і зміна статусу (заплановано → виконується/пауза → завершено, або скасовано/заблоковано). Задачі поки створюються тільки вручну — автоматичного планування з дефіциту складу ще немає (ТЗ розділ 13).
- **Рецептури блендів** — технологічні карти (компоненти зеленої кави й вага на партію 20 кг), для планування станції обсмажки.
- **Замовлення** — завантаження SAP-файлу (меню "⋯"), рядки додаються без дублів (звірка по номеру замовлення + коду товару), товар і клієнт яких ще немає в довідниках додаються автоматично, звіт після імпорту (скільки нових/дублів/пропущено/нових товарів/клієнтів). Статус (нове / в роботі / відвантажено / скасовано) міняється вручну по номеру замовлення.
- **Клієнти** — наповнюється автоматично з замовлень; вручну можна проставити "Групу партнера" (об'єднати кілька ФОП/ТОВ одного фактичного партнера, наприклад Капран), тип і менеджера.
- **Розхідники** — окремий облік пакувальних матеріалів (плівка, пачки, коробки, картонні коробки; наліпки поки без даних, каталог готовий приймати їх кнопкою "+ Матеріал"), кожен зі своїм залишком і рухами (приймання від постачальника, списання у виробництво, повернення, брак, коригування, інвентаризація), полем "Період замовлення" (скільки днів іде постачання) для майбутнього розрахунку "коли й скільки замовляти".
- **Специфікація товару** — кнопка "Специфікація" в рядку кожного товару на вкладці "Товари": прив'язує до товару, яка пачка/плівка/наліпка (перед і зад окремо) на нього йде і в яку коробку пакується при відвантаженні. Поки жодних прив'язок не заповнено — потрібні дані від Тетяни, яка пачка/плівка/коробка йде на який товар.

Чого ще немає (наступні кроки): автоматичне списання розхідників при виконанні задачі/відвантаженні (потребує спочатку заповнених специфікацій), зелена кава/напівфабрикат (окремі рівні запасів), автоматичне списання готової продукції зі складу при відвантаженні замовлення, автоматичне планування задач станцій з дефіциту складу, дашборд із завантаженістю станцій і прогнозом розхідників (ТЗ розділ 26 явно каже не починати дашборд до стабілізації операційних даних), звіт по виконаній роботі станцій за період, планшетний інтерфейс для працівників станцій.

## Як розгорнути на Railway (одноразово)

1. У тому ж проєкті Railway (`zesty-enthusiasm`, де вже є бот і Postgres) — **+ New → GitHub Repo** → обери той самий репозиторій `freshblack-bot`, але в налаштуваннях нового сервісу постав **Root Directory** = `warehouse`.
2. У Variables нового сервісу додай:
   - `DATABASE_URL` = `${{ Postgres.DATABASE_URL }}` (та сама база, що й у бота)
   - `WAREHOUSE_USER` і `WAREHOUSE_PASSWORD` — придумай логін/пароль для входу (це не обов'язково, але без них сторінка відкрита будь-кому за посиланням)
3. **Settings → Networking → Generate Domain** — отримаєш публічну адресу типу `https://warehouse-production.up.railway.app`.
4. Відкрий цю адресу в браузері — введи логін/пароль (якщо задавала) — готово.
